# Hail_2（对原版有大改动，请认真阅读readme）

这是基于 [Hail](https://github.com/aistra0528/Hail) 修改的 Android 应用管理工具。默认安装名称为“万年历”，包名为 `com.aistra.calendar`。打开应用后先显示日历，完成指定操作才会进入应用管理界面。

本分支保留了 Hail 的应用停用、隐藏、暂停、强行停止、标签管理和自动操作能力，并调整了设置结构与批量操作方式。

> 对系统应用执行停用、隐藏或暂停可能导致系统异常，严重时可能无法正常开机。操作系统应用前，请确认自己知道如何通过 ADB、Root 或 Recovery 恢复。

## 1. 功能和使用方法

### 1.1 首页-添加和管理应用

设置页中“权限”和“默认模式”下方的“添加操作应用”用于选择需要管理的软件：

1. 找到目标应用并勾选。
2. 返回“首页”，应用会出现在当前标签中。
3. 点击应用图标可启动应用。应用处于停用、隐藏或暂停状态时，软件会先尝试恢复再启动。
4. 长按应用可执行操作、恢复、定时任务、置顶、白名单、标签分组、复制包名或移出首页。

应用页面支持按名称、首次安装时间和最近更新时间排序，也可以筛选用户应用、系统应用以及已操作或未操作的应用。底部导航栏不再显示“应用”按钮，需要添加应用时从设置页进入。

如果某个首页应用已经被其他工具卸载，它仍会保留在原标签中，但会统一排到正常应用之后。可长按该条目并选择“从首页中移除”来清理记录。

### 1.2 首页-标签和独立模式

首页可以按标签管理应用。同一个应用可以加入多个标签。

- 长按标签可重命名标签，并为该标签选择**独立模式**。
- 标签模式只显示当前权限支持的操作。
- 标签模式的**优先级高于**设置中的默认模式。
- 标签没有设置独立模式时，使用设置页的默认模式。
- 一个应用同时属于多个独立模式标签时，按首页标签顺序采用第一个匹配的模式。

例如，默认模式为“停用”，可以让 A 标签继续使用停用，让 B 标签单独使用隐藏。执行全部操作时，软件会分别处理，并显示“A 标签已停用”“B 标签已隐藏”之类的结果。

### 1.3 首页-当前标签和全部应用操作

首页右下角按钮用于处理当前可见标签：

- 操作可见：按照当前标签的模式处理该标签中的非白名单应用。
- 恢复可见：按照当前标签的模式恢复该标签中的应用。

点击按钮后会展开两个独立选项，按钮图标同时旋转。再次点击可收起菜单。

首页右上角菜单保留以下批量功能：

- 全部操作：没有独立标签模式的应用使用默认模式；设置过独立模式的标签使用标签模式。
- 全部恢复：按对应模式恢复应用。
- 操作非白名单应用。
- 从剪贴板或当前已处理应用导入。
- 导出当前标签或全部应用的包名。

### 1.4设置-选择权限和默认模式

第一次使用时，先进入设置页选择“权限”，再选择“默认模式”。可选权限及对应操作如下：

| 权限             | 强行停止 |  停用  |  隐藏  |  暂停  |
| ---------------- | :------: | :----: | :----: | :----: |
| Root             |   支持   |  支持  |  支持  |  支持  |
| Shizuku          |   支持   |  支持  |  支持  |  支持  |
| Dhizuku          |  不支持  | 不支持 |  支持  |  支持  |
| 设备所有者       |  不支持  | 不支持 |  支持  |  支持  |
| 炼妖壶 / Insular |  不支持  | 不支持 |  支持  |  支持  |
| 特权系统应用     |   支持   |  支持  | 不支持 | 不支持 |

具体可用情况还会受到 Android 版本、系统限制和授权方式影响。例如部分非 Root 的 Shizuku 环境无法执行隐藏操作。

几种模式的区别：

- 强行停止：结束应用当前进程，应用之后仍可能被系统或其他事件重新启动。
- 停用：应用无法运行，桌面入口通常会消失，可通过“启用”恢复。
- 隐藏：应用会从启动器和普通应用列表中隐藏，可通过“取消隐藏”恢复。
- 暂停：限制用户启动应用并隐藏通知，但不保证应用后台进程完全停止。

执行操作和恢复时应保持权限一致。更改权限或标签模式前，建议先恢复已经处理的应用。

### 1.5设置-自动操作

设置页“自动操作”可以在锁屏后处理首页应用，并设置操作延时。还可以选择：

- 充电时跳过。
- 跳过前台应用。
- 跳过正在显示通知的应用。

跳过前台应用需要授予使用情况访问权限；跳过通知应用需要授予通知读取权限。

### 1.6设置-生物识别和界面设置

设置页还保留以下选项：

- 生物识别验证，位于“自定义”分组最上方。
- 浅色、深色或跟随系统主题。
- 首页字体大小。
- 模糊搜索。

“关于”不再占用底部导航栏，可在“设置 > 其他 > 关于”中打开。

### 1.7 增加日历伪装功能

开启后，桌面入口会以“万年历”的名称和日历图标显示。打开应用时先进入日历页面，可查看阳历、农历，并通过左右滑动切换月份。

进入管理页面的方法：先双击年份，再在 3 秒内长按月份。成功进入后，本次运行期间不会再次显示日历；关闭并重新打开应用后，日历页面会恢复。

如不需要此功能，可在“设置 > 自定义”中关闭“启用日历隐藏”。关闭后会恢复 Hail 的桌面名称和默认图标，之后打开应用将直接进入主界面。

### 1.8 无图标应用启动器

设置页新增独立的“无图标应用启动器”分组，使用方法如下：

1. 先选择 Root、Shizuku 或特权系统应用权限，再开启“无图标应用启动器”。其他权限目前不能修改应用的桌面入口，操作时会提示无权限。
2. 点击“管理页面”进入应用列表。列表不显示应用图标，只显示应用名称、隐藏或恢复图标按钮以及启动按钮。
3. 点击隐藏按钮后，对应应用的桌面图标会消失，但应用不会被停用，仍可在管理页面中点击启动按钮打开。
4. 点击恢复按钮可让应用图标重新出现在桌面。已经隐藏或恢复过的应用会优先排列，最近操作的排在前面。
5. 页面支持搜索，并可按名称、安装时间或更新时间排序，也可以筛选用户应用、系统应用、已隐藏应用和图标可见的应用。

关闭“无图标应用启动器”总开关时，已隐藏的图标会暂时恢复；再次开启后，会按照之前保存的记录重新隐藏。该功能只处理桌面启动图标，不会让应用从系统设置中消失。



## 2. 相对原版增加和修改的功能

1.将工作模式拆成“权限”和“默认模式”两行，先选授权方式，再选该权限支持的操作。

2.日历伪装：显示阳历、农历，滑动切换月份；增加“启用日历隐藏”开关；当前解锁动作为双击年份后长按月份。关闭后恢复 Hail 的桌面名称和默认图标。

3.标签独立模式：不同标签可分别使用停用、隐藏、暂停等操作，批量操作会根据各标签模式分别执行。

4.增加“无图标应用启动器”，可单独隐藏或恢复其他应用的桌面图标，并从管理页面启动这些应用。

5.首页右下角增加“操作可见/恢复可见”菜单。已卸载应用的残留记录自动排到最后。

6.设置页增加“添加操作应用”入口。

7.应用默认名称改为“万年历”，使用新的日历图标，包名改为 `com.aistra.calendar`，APK 文件名改为 `Calendar-v版本号.apk`。



## 3. 已删除的功能

为了精简设置页和不再使用的入口，本分支删除了：

- 图标包设置。
- 灰度图标。
- 紧凑图标。
- 合成自适应图标。
- T9 九键搜索。
- 整个“快捷方式”设置分组，包括添加固定快捷方式、动态快捷方式操作和清除动态快捷方式。
- 快捷设置磁贴的操作设置、磁贴服务及相关代码。
- 底部导航栏中的“关于”按钮。关于页面本身仍然保留，入口已移到设置页。
- 底部导航栏中的“应用”按钮。应用选择页面仍然保留，入口已移到“设置 > 添加操作应用”。
- 首页右上角菜单中的“操作可见 / 恢复可见”。功能没有取消，已经移动到右下角按钮。
- 关于页面中的 群组、QQ群、F-Droid 和翻译入口。

## 4. MiPush Enhance 兼容性

支持[New MiPush Enhance](https://github.com/Xposed-Modules-Repo/io.github.codecodegogogo.newmipushenhance) 冻结推送。使用该模块时，应按模块说明设置 LSPosed 作用域。当前标签如果单独选择了“停用”，标签内的应用也可以使用。
